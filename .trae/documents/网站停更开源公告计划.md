# 网站停更开源公告计划

## Summary

- 目标：为当前站点发布统一公告，明确说明项目已开源、仓库地址为 `https://github.com/NingZeStudio/fcl-to-zl2_controller`、当前站点因新控件转换网站正在部署而停止维护，并说明新站公开后此公告会同步更新。
- 呈现方式：保留现有转换器和编辑器功能，在站点顶部和关键说明区域加入显著公告，不改成纯公告落地页。
- 文档策略：重写 `README.md` 开头，新增醒目的项目状态公告，同时保留后续功能说明和使用文档内容。

## Current State Analysis

- `src/App.vue`
  - 当前是单页应用主入口，包含转换器与编辑器两个页签。
  - 转换器区域已有一个“重要提示” `Alert`，但仅描述颜色值与精度问题，不涉及项目状态。
  - 页脚仅有“基于 FCL 和 ZL2 控件系统文档开发”，没有开源仓库、维护状态或迁移说明。
- `src/components/Alert.vue`
  - 现有 `Alert` 组件足够承载公告内容，不需要新增组件即可插入全站公告块。
- `README.md`
  - 当前顶部仍以“在线使用”和旧站地址为主，没有说明仓库已开源、站点停更或迁移状态。
- `START_HERE.md`
  - 当前仍引导用户直接运行和使用当前站点，没有提醒该站点已停止维护。
- `index.html`
  - 页面标题仍是普通产品名 `FCL 到 ZL2 控件转换器`，没有体现项目状态。

## Proposed Changes

### 1. 更新 `src/App.vue`

- 在顶部导航上方新增全站公告区，使用现有 `Alert` 组件承载，文案明确包含以下信息：
  - 项目已开源。
  - GitHub 仓库地址：`https://github.com/NingZeStudio/fcl-to-zl2_controller`。
  - 当前网站因新控件转换网站正在部署，现站不再维护。
  - 新站公开后，此公告会同步更新。
- 在转换器主标题下的副标题区域补充一行较短的状态说明，避免用户只看到功能介绍却错过停更信息。
- 在编辑器视图标题区加入同样的状态说明，确保切到编辑器页签的用户也能看到。
- 在页脚补充两个常驻信息：
  - 开源仓库入口。
  - “当前站点停止维护，后续请关注公告更新”的说明。
- 文案语气统一为“公告/迁移说明”，避免继续强调“在线服务正在维护中”。

### 2. 更新 `README.md`

- 将现有“在线使用”之前改写为“项目状态公告”开场区，内容包括：
  - 项目已开源。
  - GitHub 仓库地址。
  - 当前站点不再维护。
  - 原因是正在部署新的控件转换网站。
  - 新站公开后，公告内容会同步更新。
- 保留旧站访问地址，但降级为“历史在线地址/旧站入口”，避免继续把它呈现为主入口。
- 在公告之后保留现有“功能特性”“使用说明”“转换规则”等内容，减少对现有文档可用性的破坏。
- 将原有带图标和较强营销感的标题文案收敛为更中性的项目说明，和“已停更但已开源”状态保持一致。

### 3. 更新 `START_HERE.md`

- 在文档开头增加简短公告，说明：
  - 项目已开源。
  - 当前仓库仍可本地运行与参考。
  - 当前线上站点不再维护。
  - 新站部署完成后会同步公告。
- 保留本地开发/启动步骤，但将语义从“推荐直接使用当前站点”调整为“如需研究或自部署，可继续本地运行”。
- 将“获取帮助/项目说明”部分增加 GitHub 仓库链接，和 `README.md` 状态保持一致。

### 4. 更新 `index.html`

- 调整浏览器标签页标题，使其体现项目状态，例如在原标题后追加“已开源 / 停止维护”。
- 目的不是替代页面公告，而是让从书签或标签页进入的用户也能第一时间感知当前状态。

## Assumptions & Decisions

- 决策：采用“顶部公告 + 保留功能”的方式，不移除转换器与编辑器现有能力。
- 决策：`README.md` 采用“重写开头公告”的方式，不把整个 README 改成纯归档页。
- 决策：仓库地址在站点公告、页脚、`README.md`、`START_HERE.md` 中保持一致，统一使用 `https://github.com/NingZeStudio/fcl-to-zl2_controller`。
- 决策：暂不写入新站 URL，因为用户未提供新站地址；当前仅说明“正在部署，公开后同步更新”。
- 假设：当前线上域名仍可访问，因此 README 中保留旧站链接，但降级为历史入口而非主推荐入口。
- 假设：本次只覆盖站点主界面与核心说明文档，不扩散修改所有开发文档和控件文档，避免过度改动。

## Verification Steps

- 检查 `src/App.vue` 公告是否在默认进入页面即可看见，且切换到“编辑器”页签后仍能看到停更状态信息。
- 检查公告文案是否完整包含以下四点：已开源、GitHub 地址、当前站点不再维护、公告后续会同步更新。
- 检查 `README.md` 顶部是否优先展示项目状态公告，并确认旧站地址不再被描述为唯一主入口。
- 检查 `START_HERE.md` 是否与 `README.md` 的项目状态一致，没有继续暗示当前线上站点仍为维护中的主站。
- 检查 `index.html` 页面标题是否成功反映“已开源 / 停止维护”状态。
- 完成改动后运行一次类型检查或构建验证，确保公告文案插入后未引入 Vue 模板或 TypeScript 错误。
